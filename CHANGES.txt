Task log (kept per task so edits are easy to follow)

Task: video player fails on large / old files ("Cannot play this file")
- PlayerActivity: recovery chain on any playback error, resuming at the last good position:
  ExoPlayer -> VLC hardware -> VLC software -> one retry 8s further on (damaged stretch) -> dialog.
  Engine choice in settings is now only the starting engine; a failure always falls back.
- PlayerActivity: events from a replaced / closed engine are ignored (no duplicate dialogs, no NPE after close).
- PlayerActivity: error dialog shown once, never on a closing screen, closing it exits the player.
- PlayerActivity: failed engine reporting position 0 no longer erases the saved resume position.
- PlayerActivity: every new file starts again with the preferred engine after a fallback.
- ExoEngine: one automatic re-prepare on a transient decode/IO error before falling back; removed unused field.
- VlcEngine: software mode drops late frames (no stalls on huge files), 1.5s read-ahead cache,
  views detached on the UI thread and stop/release on a worker thread, no calls on a released player.
- Media.resumeKey(): files opened from other apps (no MediaStore id) no longer share one resume slot.
- Strings: new fallback_sw / recover_skip, updated play_error_msg / set_engine_sub (ar + en).
Dead code: scan found no unused classes, methods, imports or resources; removed unused fields in the player.

Task: file opened from a file manager fails right after seeking
- PlayerActivity: recovery restarts from the last position that really played (not the seek target the failed engine reports).
- PlayerActivity: the error dialog now lists every attempt (engine, error code, position) to tell a damaged file from an app bug.

Task: diagnose unreadable file
- VlcEngine: "open" error now includes the exception type and message (shown in the error dialog).

Task: seeking fails on files opened from outside the app (and two different files, so not damaged files)
- PlayerActivity: a file from another app (content:// without a MediaStore id) is checked for random access;
  if the source is not seekable it is copied to cache/play first (progress %, space check) and the local copy is played.
- PlayerActivity: last-resort step of the recovery chain: when every engine fails on the original source,
  copy the file to the cache and retry the whole chain on the copy from the last good position.
- Cache copy is removed when the file changes and when the player closes. New string preparing_file (ar + en).

Task: files opened from a file manager fail with SecurityException (FileProvider permission denied)
- OpenActivity: forwards the sender's temporary read grant (data + ClipData + FLAG_GRANT_READ_URI_PERMISSION) to PlayerActivity / ViewerActivity.
  Cause: the grant belonged to OpenActivity, which closes right away, so later reads (seeking, cache copy, VLC) were denied.
